# Native initial routing memory in the 2.0 update

The native initial-routing provider previously retained routers under historical thread IDs, duplicated SpeedyALT preparation per worker and kept every transport query indefinitely. This change applies to the 2.0 worktree; it is not a legacy 1.8 backport.

`NetworkBasedTransportCosts` now owns one synchronized default factory per built provider. Immutable graph and landmark preparation is shared within that provider; mutable path calculators stay in a provider-owned weak worker map. A new worker retires terminated predecessors; weak keys also release forgotten worker objects on subsequent accesses. Discarding the provider releases its routers even when the calling thread remains alive. No thread-local value can retain an abandoned provider's network. Reusing a builder produces separate preparation, so changed lower cost bounds cannot reuse inadmissible landmarks. Explicit custom factories retain their existing ownership contract.

Actual vehicle results and neutral jsprit preparation use separate bounded insertion-order caches. Defaults are 1,000,000 and 16,384 entries per provider; `Builder.setCacheLimits(transportEntries, neutralEntries)` accepts positive overrides. Hits use a concurrent map without access-order bookkeeping. Only cache insertion takes the write lock; path calculations remain outside it. Eviction drops memoized results, preserving directed endpoints, original time bins and vehicle type. The network/profile must remain stable during the provider's lifetime, as before. Limits reduce retained data; a limit too small for the working set can increase recomputation.

The pinned jsprit 2.0.0 `JobNeighborhoodsOptimized` replacement preserves native neighborhood capacity and directed distance calls. It stores indices up to 65535 in unsigned `char` rows and uses full-width integer rows for larger problems. Reusable primitive stable mergesort scratch arrays replace per-pair temporary objects. Equal distances keep original encounter order; NaN, infinities and signed zero retain `Double.compare` semantics. Quadratic distance work is unchanged. The implementation is explicitly excluded from the upstream dependency during shading so only the reviewed replacement is packaged.

For the certified default free-flow profile, `NativeModalTransportCosts` uses one time slice across the normal nonnegative MATSim scheduling horizon (below `Integer.MAX_VALUE` seconds). That certificate requires no network change events and the built-in callback; explicit callbacks remain uncertified. Directed endpoints and vehicle types remain distinct. This removes duplicate time-bin calculations instead of merely evicting them. Network and vehicle profiles must remain unchanged during a provider's lifetime. Accumulating travel time from zero can change floating-point rounding compared with the former half-hour origin, so exact route equivalence is verified on concrete seeded searches rather than promised for arbitrary tight time windows.

Regression coverage: `NativeMemoryLifecycleTest`, `NativeBoundedCacheTest`, `HagridCompactNeighborhoodTest`, `NativeConstantProfileCacheTest`, existing native routing tests and the full reactor suite. Independent paired probes compare original and updated 2.0 behavior, including real jsprit searches and routed/validated Hannover carrier plans. Process peak RSS, retained heap and cumulative allocations must be reported separately; a component improvement is not a measured reduction for an entire regional 150-iteration run.

The large DHL probes use assigned stop links and U-turn penalty zero. Equal final plans after 100 iterations do not mean every intermediate solution was compared. Joint approach-direction selection remains in `tools/benchmarks/directions`, whose current fixture is one vehicle and 69 physical halts. Its precomputed matrices bypass the native provider: regression there validates the neighborhood change, not a native-cache speedup. General multi-vehicle production integration, verified DHL physical stop options and calibrated turn/crossing costs are separate outstanding work.
